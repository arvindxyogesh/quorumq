- Payload 256 bytes; closed-loop runs use 32 producers and 64 workers

Submit-to-ack latency runs from the start of a Submit call to the end of the
worker's successful Ack for that job: submit commit, time queued, claim commit,
worker poll delay and ack commit. Every write is committed by a Raft quorum and
fsynced before it is acknowledged.

## Chaos: leader killed repeatedly under load (3 nodes)

`pkill -KILL` (SIGKILL) of the current leader's quorumq-server process every 15-25s while
producers submit at 300/s; the killed broker is restarted on the same node with the same
data directory and rejoins as a caught-up follower before the next kill. The probe runs
on the killed broker's node, started by the same command as the kill.
Failover time is measured by `quorumq-load probe` from the kill until a Submit is
acknowledged again (10 ms retry interval).
